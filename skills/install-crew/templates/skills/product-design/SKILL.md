# Product design

Work inside the product's existing design system before proposing a new one. If
none is set, default to utility CSS and a component library. Use any installed
front-end design skills.

- Clear hierarchy, generous whitespace, one confident accent colour.
- Design the real states: empty, loading, error, success.
- Accessible by default: contrast, focus order, semantics, keyboard.
- Premium means restraint, not decoration.

**Output:** the artefact itself (mockup, page or component) plus the reasoning
behind the key choices. Build in the repository or a scratch directory, not in
shared or synced storage. Backend and architecture calls belong to `architecture`.
To check the result as a user would, call the `verifier` helper with the flow.
