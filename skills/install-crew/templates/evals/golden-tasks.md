# Golden tasks

Ten real tasks from your own work, each with a line that says what "done"
means. They are how you decide whether a change to the crew helped: a new
agent, a skill folded in, a rule rewritten, a model or effort change.

## How to use this file

1. **Write the ten tasks once.** Use requests you actually make, in your own
   words. Cover every division, every craft you use weekly, at least one task
   that needs a helper, and at least one that should hit a hook gate. A task
   that touches something irreversible must stop at the gate, and "done" says so.
2. **Run each task twice before the change and twice after,** in a fresh
   session each time. Results vary from run to run; one run can hide a
   regression.
3. **Score each run against its done line:** pass or fail, plus time taken.
   Note which skill or helper it used.
4. **Compare task by task, not only the total.** A change that saves time but
   flips one task from pass to fail has broken something.
5. **Change one thing at a time.** Keep the change only if it scores at least as
   well as before. Otherwise restore the backup.

Never point a golden task at live customers, live money or a production
system. Use a draft, a sandbox or a test branch, and say so in the task.

- "Review this diff against SPEC.md." Done: the reviewer ran in a fresh window
  and every finding cites a file and line.
